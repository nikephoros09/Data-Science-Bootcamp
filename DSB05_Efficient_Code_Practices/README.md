# Efficient code practices

### Exercise 01. Map

Реализована функция, которая формирует список адресов Gmail из исходного списка из 25 адресов с использованием `map()`.

Проведено сравнение трёх подходов:

* обычный цикл;
* list comprehension;
* `map()`.

Для измерения времени выполнения использован модуль `timeit`. Результаты трёх вариантов отсортированы по времени выполнения от самого быстрого к самому медленному.

Пример результата:

```text
it is better to use a map
29.32016281 vs 54.620376492999995 vs 55.99120069
```

Дополнительно проверено, что результаты работы различных реализаций соответствуют поставленной задаче. При этом результаты не обязаны быть полностью идентичными во всех деталях.

### Exercise 02. Filter

Добавлена реализация фильтрации с использованием `filter()`.

Скрипт принимает два аргумента:

1. название используемого метода — `loop`, `list_comprehension`, `map` или `filter`;
2. количество вызовов функции для проведения бенчмарка.

В зависимости от выбранного метода выполняется соответствующее количество вызовов, после чего выводится затраченное время.

Примеры:

```text
$ ./benchmark.py loop 10000000
6.230267604

$ ./benchmark.py list_comprehension 10000000
6.214286791

$ ./benchmark.py map 10000000
3.063598874
```

Таким образом, один скрипт позволяет сравнивать производительность всех четырёх вариантов обработки данных.

### Exercise 03. Reduce

Реализованы два способа вычисления суммы квадратов чисел до заданного значения:

* с использованием обычного цикла;
* с использованием `reduce()` из модуля `functools`.

Например, для значения `5` вычисляется:

```text
1 + 4 + 9 + 16 + 25 = 55
```

Скрипт принимает название метода, количество вызовов для бенчмарка и значение, до которого необходимо вычислить сумму квадратов.

Примеры запуска:

```text
$ ./benchmark.py loop 10000000 5
6.230267604

$ ./benchmark.py reduce 10000000 5
3.063598874
```

Производительность двух реализаций сравнивается с помощью `timeit`.

### Exercise 04. Counter

Сгенерирован список из одного миллиона случайных чисел в диапазоне от `0` до `100`.

Реализованы собственные функции для:

* подсчёта количества каждого уникального значения с использованием словаря;
* определения десяти наиболее часто встречающихся чисел.

Те же операции выполнены с использованием `Counter` из модуля `collections`.

Проведено сравнение времени выполнения собственного решения и решения на основе `Counter`:

```text
my function: 0.4501532
Counter: 0.0432341
my top: 0.1032348
Counter's top: 0.017573
```

Результаты демонстрируют преимущество `Counter` как по скорости подсчёта значений, так и при определении наиболее часто встречающихся элементов.

### Exercise 05. Generator

Для сравнения эффективности работы с большими файлами подготовлена обработка датасета MovieLens `ml-25m`, в частности файла `ratings.csv`.

Созданы два скрипта:

* `ordinary.py` — считывает все строки файла в список, после чего выполняется итерация по полученному списку;
* `generator.py` — использует генератор с `yield` и обрабатывает файл построчно, не загружая все данные в память одновременно.

Оба скрипта принимают путь к файлу в качестве аргумента и выводят пиковое использование памяти, а также суммарное время работы в пользовательском и системном режиме.

Пример результатов:

```text
$ ./ordinary.py ratings.csv
Peak Memory Usage = 2.114 GB
User Mode Time + System Mode Time = 5.77s

$ ./generator.py ratings.csv
Peak Memory Usage = 0.005 GB
User Mode Time + System Mode Time = 9.04s
```

Сравнение показывает основное преимущество генератора: значительно меньшее потребление оперативной памяти. При этом последовательное чтение данных с помощью `yield` может занимать больше времени, чем предварительная загрузка всего файла в список.
