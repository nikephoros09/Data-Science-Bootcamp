# Intro to Python: Package management and virtual environment

### Exercise 00. Виртуальное окружение

Создано виртуальное окружение с именем пользователя и выполнена его активация.

С помощью библиотеки `os` определено текущее виртуальное окружение. Создан скрипт `venv.py`, который запускается из командной строки и выводит путь к активному окружению:

```text id="6x4q2j"
$ ./venv.py
Your current virtual env is /Users/McShtuder/shtuder
```

После выполнения работы виртуальное окружение деактивируется. Повторный запуск скрипта после деактивации позволяет увидеть отличие в состоянии окружения.

### Exercise 01. Установка пакета

В созданное виртуальное окружение установлена библиотека `termgraph`, предназначенная для построения графиков и диаграмм непосредственно в терминале.

Подготовлен файл с исходными данными для визуализации и создан shell-скрипт `pies_bars.sh`, который выполняет построение графика с использованием другой цветовой схемы.

Скрипт содержит только команды, необходимые для создания визуализации, без активации и деактивации виртуального окружения.

### Exercise 02. Установка нескольких библиотек

Для управления зависимостями подготовлен файл `requirements.txt`, через который одновременно устанавливаются необходимые библиотеки `BeautifulSoup` и `PyTest`.

Создан скрипт `librarian.py`, который:

* проверяет, что запущен внутри правильного виртуального окружения;
* устанавливает необходимые библиотеки;
* получает список установленных пакетов;
* выводит информацию об установленных библиотеках;
* сохраняет список зависимостей в `requirements.txt`.

Пример полученного списка:


Если скрипт запускается вне требуемого виртуального окружения, вызывается исключение.

### Exercise 03. BeautifulSoup

С помощью библиотеки `BeautifulSoup` реализован разбор страницы Yahoo Finance и получение финансовых данных для указанной компании.

Скрипт `financial.py` принимает два аргумента:

1. тикер компании;
2. название требуемого поля таблицы.

Например:

```text id="p82m9s"
$ ./financial.py 'MSFT' 'Total Revenue'
('Total Revenue', '134,249,000', '125,843,000', '110,360,000',
'89,950,000', '85,320,000')
```

Результат возвращается в виде кортежа с названием поля и соответствующими значениями.

В программу также добавлена задержка выполнения на 5 секунд с помощью `sleep`, необходимая для последующего анализа производительности.

При отсутствии страницы или запрашиваемого поля вызывается исключение.

### Exercise 04. Профилирование

Для анализа производительности `financial.py` применён встроенный профилировщик `cProfile`.

Получены несколько вариантов статистики выполнения программы:

* `profiling-sleep.txt` — функции отсортированы по общему времени выполнения с учётом `time.sleep(5)`;
* `profiling-tottime.txt` — результаты после удаления `time.sleep(5)`;
* `profiling-http.txt` — результаты после замены HTTP-клиента на более эффективный вариант;
* `profiling-ncalls.txt` — функции отсортированы по количеству вызовов;
* `pstats-cumulative.txt` — с использованием `pstats` получены пять функций с наибольшим совокупным временем выполнения.

Для сравнения производительности создан отдельный скрипт `financial_enhanced.py`.

Таким образом, проведён анализ времени выполнения, количества вызовов функций и влияния HTTP-клиента на производительность программы.

### Exercise 05. PyTest

Для проверки корректности `financial.py` созданы автоматические тесты с использованием библиотеки `PyTest`.

Для функций программы подготовлены тесты, проверяющие:

* корректное получение значения `Total Revenue` для заданного тикера;
* тип возвращаемого результата — `tuple`;
* возникновение исключения при передаче некорректного тикера.

Для каждой проверяемой функции создано не менее трёх тестов.

Тесты сохранены в файле `financial_test.py` и запущены с помощью `PyTest`. Все проверки должны завершаться успешно, подтверждая корректность работы программы и обработки ошибочных входных данных.

1. In ex03, we are sure that you used one or more functions. For each function, create at least three tests using the PyTest library. Check if your script provides the correct information for each request:
    - If I ask for Total Revenue, does it return the total revenue for the given ticker?
    - Is the return type a tuple?
    - If I enter an invalid ticker name, does an exception occur?
2. Add the tests to the code in your `financial.py` script. Save the file in your directory as `financial_test.py`. Run PyTest. Your tests should have passed. If not, work on your script to prepare it.
